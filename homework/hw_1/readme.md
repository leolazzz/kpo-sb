# Московский зоопарк - ERP система

## Обзор решения

Данное приложение реализует ERP-систему для Московского зоопарка с соблюдением принципов SOLID и использованием Spring DI-контейнера.

## Принципы SOLID в реализации

### 1. Single Responsibility Principle (SRP)
- `ZooService` отвечает только за управление животными и вещами
- `VeterinaryClinic` отвечает только за проверку здоровья животных
- `ConsoleApplication` отвечает только за взаимодействие с пользователем

### 2. Open/Closed Principle (OCP)
- Код открыт для расширения: можно добавлять новые типы животных, наследуясь от `Herbo` или `Predator`
- Новые типы вещей можно добавлять через наследование от `Thing`
- Не требуется изменять существующий код для добавления новой функциональности

### 3. Liskov Substitution Principle (LSP)
- Все подклассы `Animal` могут быть использованы вместо базового класса
- `Herbo` и `Predator` полностью совместимы с классом `Animal`
- Конкретные животные (Monkey, Rabbit, etc.) могут использоваться везде, где ожидается `Animal`

### 4. Interface Segregation Principle (ISP)
- `IAlive` содержит только методы, связанные с живыми существами
- `IInventory` содержит только методы для инвентаризации
- Классы реализуют только те интерфейсы, которые им действительно нужны

### 5. Dependency Inversion Principle (DIP)
- `ZooService` зависит от абстракции `VeterinaryClinic` (через внедрение зависимости)
- Все зависимости внедряются через конструктор
- Высокоуровневые модули не зависят от низкоуровневых реализаций

## Использование DI-контейнера

Spring Boot используется для:
- Автоматического сканирования компонентов (`@Component`, `@Service`)
- Внедрения зависимостей через конструктор
## Запуск приложения

### Требования
- Java 17+
- Gradle

### Инструкция по запуску(linux)

1. Клонируйте репозиторий
2. Перейдите в директорию проекта
3. Запустите приложение:
```
chmod +x gradlew
./gradlew build #сборка и запуск тестов
java -jar build/libs/hw_1-1.0.0.jar #запуск консольного приложения
```
