# Антиплагиат

## Обзор системы

Данная микросервисная платформа предназначена для автоматизированной проверки студенческих работ на предмет заимствований. Система реализует следующий рабочий процесс:

- Прием учебных материалов от учащихся
- Сохранение файлов и сопроводительной информации
- Автоматический анализ текстов на наличие плагиата
- Формирование детализированных отчетов
- Создание визуализаций в формате облака слов

## Инфраструктура и порты сервисов

После выполнения команды запуска:

```bash
docker-compose up --build
```

будут доступны следующие компоненты:

- **API Gateway** — основной шлюз: http://localhost:8080
- **Сервис хранения файлов** — менеджер файлов: http://localhost:8081
- **Сервис анализа** — модуль проверки: http://localhost:8082

Документация API (Swagger UI):
- Gateway: http://localhost:8080/swagger-ui.html
- Хранилище: http://localhost:8081/swagger-ui.html

## Ключевые API-методы

Все запросы направляются через API Gateway (http://localhost:8080).

**Отправка работы на проверку:**
```
POST http://localhost:8080/api/works
Тело: multipart/form-data
  file=@<путь_к_файлу>
  studentId=<идентификатор студента>
  assignmentId=<код задания>
  studentName=<имя студента> (опционально)
```

**Получение информации о работе:**
```
GET http://localhost:8080/api/works/{workId}
```

**Запрос отчетов по работе:**
```
GET http://localhost:8080/api/works/{workId}/reports
```

**Получение облака слов:**
```
GET http://localhost:8080/api/works/{workId}/wordcloud
```

**Все работы по конкретному заданию:**
```
GET http://localhost:8080/api/assignments/{assignmentId}/works
```

## Взаимодействие микросервисов

### Сценарий 1: Загрузка новой работы

1. **Клиент → API Gateway**
   - Пользователь отправляет POST запрос с файлом через Gateway
   - Gateway проверяет формат и размер файла

2. **API Gateway → File Storing Service**
   - Gateway перенаправляет файл в сервис хранения
   - Сервис сохраняет файл на диске и записывает метаданные в БД

3. **File Storing Service → API Gateway**
   - Возвращается информация о сохраненной работе с уникальным ID

4. **API Gateway → File Analysis Service** (асинхронно)
   - Gateway запускает фоновый процесс анализа
   - Извлекается содержимое файла из хранилища
   - Отправляется запрос на проверку плагиата

5. **File Analysis Service → Внутренняя обработка**
   - Текст анализируется на предмет совпадений
   - Генерируется облако слов
   - Формируется отчет о проверке

### Сценарий 2: Запрос отчетов

1. **Клиент → API Gateway**
   - Запрос GET /works/{id}/reports

2. **API Gateway → File Analysis Service**
   - Gateway обращается к сервису анализа
   - Извлекаются все отчеты по указанной работе

3. **API Gateway → Формирование ответа**
   - Gateway объединяет данные при необходимости
   - Возвращается структурированный ответ клиенту

### Сценарий 3: Обработка ошибок

При недоступности одного из сервисов:

- **API Gateway** возвращает понятное сообщение об ошибке
- **File Analysis Service** использует fallback-режим при отсутствии БД
- **File Storing Service** проверяет доступность дискового пространства

## Алгоритм выявления плагиата
Плагиат присутствует, если существует более ранняя
сдача (другим студентом) присланной работы.
## Визуализация данных

**Облако слов** создается с использованием QuickChart API:
- Размер слова соответствует его частотности в тексте
- Цветовая палитра улучшает восприятие
- Настраиваемые параметры отображения

**Пример визуализации:**
Работа по программированию покажет крупными словами: "программирование", "java", "код", "алгоритм", "разработка"
